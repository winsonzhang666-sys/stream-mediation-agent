# 纠纷调解流式数据 · 质量要求与检修规范（数据方版）

> 面向**从零制作数据**的团队。本文件讲：数据要达到什么质量、怎么逐维度自查。**不依赖任何脚本，人工即可执行。**
> 配套《数据格式_输入输出_纯格式版.md》——字段清单与完整示例看那份；本份讲「怎样才算做对」。

---

## 0. 你要交付什么 + 一句话底线

- **交付物** = `jsonl`，每行一个案子 = 一段多轮对话（`dialogue`）+ 3–4 个「当前状态快照」（`snapshots`，每个含**五要素**：诉求 / 事实 / 争议焦点 / 证据 / 调解方案）。
- **一句话底线**：
  1. **只写对话里真出现过的**，没有就**留空**（不许编、不许猜）；
  2. **每条态度归到真正说这话的那个人**（用真名）；
  3. **状态类字段只能用规定词表里的词**；
  4. **同一件事跨快照用同一个编号，且一路带着走、不丢**。

---

## 1. 两类字段、两套规矩（**最重要，先看这个**）

五要素里的字段分两类，规矩完全不同：

| 类型 | 哪些字段 | 规矩 |
|---|---|---|
| **自由文本（grounded）** | 诉求`诉求`、事实`描述`、争议`问题`、证据`证据`、方案`内容` | 照对话**如实写**，可长可短；对话没有就**留空** |
| **状态机（闭合词表）** | 诉求`当前状态`、事实`当前状态`、事实·各方态度`态度`、争议`当前状态`、证据`提交状态`、方案`当前状态`、方案·各方态度`态度` | **只能从下面词表里选一个词**，不许自造、不许改写、不许往词里塞细节 |

### 1.1 状态机字段的闭合词表（逐字照用，出这个范围就是错）

| 字段 | 允许的取值（**只能选其一**） |
|---|---|
| 诉求 · `当前状态` | 新提出 / 对方尚未回应 / 协商中 / 对方提出反方案 / 条件接受 / 部分接受 / 接受 / 已谈拢 / 拒绝 / 已撤回 / 已放弃 / 未解决 |
| 事实 · `当前状态` | 一方说了待回应 / 双方确认 / 部分认可 / 对方否认 / 待材料核实 / 争议中 / 已更正 / 已撤回 |
| 事实 · 各方态度 · `态度` | 认可 / 部分认可 / 否认 / 主张 / 未回应 |
| 争议焦点 · `当前状态` | 争议中 / 范围缩小 / 暂时共识 / 部分共识 / 重新争议 / 已解决 / 搁置 |
| 证据 · `提交状态` | 已提及未上传 / 已提交 / 已核对 / 无法提交 |
| 调解方案 · `当前状态` | 内部草案 / 已提出 / 部分达成 / 达成一致 / 失效 / 中止 |
| 调解方案 · 各方态度 · `态度` | 原则同意 / 要求修改 / 同意 / 拒绝 |

### 1.2 铁规：**细节绝不塞进状态词**

状态词只表达「到了哪一步」，具体的**谁、多少钱、什么条件、待谁确认**一律写进同一项的**自由文本字段**。

- ✅ 对：`态度=部分认可` ＋ 描述里写「李四只认可其应得的六分之一份额」。
  ❌ 错：`态度=认可六分之一份额`（把细节塞进了状态词）。
- ✅ 对：诉求`当前状态=协商中` ＋ 诉求文本写「物业已提折中方案，待张三回应」。
  ❌ 错：`当前状态=协商中（物业已提方案待张三回应）`。

## 2. 质量要求（八条硬规矩，逐条必须满足）

### ① GROUNDING：不编造，宁可留空
- 每一条内容都要能在**对话**里指到出处；对话没说的姓名 / 金额 / 日期 / 证据 / 事件，**一律留空**，绝不脑补或提前写「还没发生的事」。
- 这叫 **abstention（留空）**：信息不足时留空是**正确**的，硬编才是错。

### ② 归属准确：态度归到真正说话的人
- 每条态度记到**对话里真正说这句话的那个人**（写真名），绝不张冠李戴。
- 方向按其**本人原话**记（主张 / 认可 / 否认 / 部分认可 / 未回应）。
- **在场但没表态的共同当事人，不要并进方态**（谁没开口就别替他登记态度）。
- 用**真名**，不许用「申请人 / 被申请人 / 对方 / 某」这类角色词占位。

### ③ 确认严格：别把「没反对」当「同意」
- **沉默 ≠ 确认**：一方说了、另一方没吭声 → 记「一方说了待回应」，不是「双方确认」。
- **调解员转述 / 概括 ≠ 当事人确认**：只有当事人**本人亲口**认可才算他认可。
- **「双方确认」** 只有在**两方各自都有本人明确认可**时才成立；两方只都认的那部分才确认（都认「有欠费」但金额还争 → 只确认「有欠费」，金额进争议焦点）。
- 带**任何条件**的认可 → 记`条件接受`，不是无条件`接受`。
- 一方只提**替代 / 反方案** → 记`协商中` / `对方提出反方案`，别记「部分接受」原诉求。
- **「先放一放 / 保留另行主张」≠ 撤回**；只有明确「不要了 / 放弃」才记`已撤回` / `已放弃`。

### ④ 状态只用词表 + 细节挪描述
见 §1.1 / §1.2。状态机字段 **100% 落在词表内**，是硬指标。

### ⑤ 编号稳定 + 一件事一个号
- 编号前缀固定：诉求 `claim_`、事实 `fact_`、争议 `issue_`、证据 `evidence_`。
- **同一件事，跨快照永远用同一个编号**；新增项在该类型**当前最大号**上顺延。
- **数额 / 内容变化 = 更新老编号**（改它的字段），**绝不另开新号**。例：诉求金额从 5 万变 6 万 → 改 `claim_002`，不许新开 `claim_003` 并存。
- **一个现实事项只给一个号**，不许同一件事在 事实 / 争议 / 证据 里重复登记成多个号。
- 撤回 / 解决 / 放弃 = 把`当前状态`改成对应词（`已撤回`/`已解决`/`已放弃`），**保留该项，不许从快照里删掉**。

### ⑥ 累积不擅删：每个快照都是「此刻的全量」
- 每个快照 = **截止到 `cutoff_turn` 为止的完整当前状态**，不是只写「这一段新增了啥」。
- 前面快照出现过、**现在仍然有效**的项，**必须继续带在后面的快照里**（同号、更新其状态），不许中途凭空消失。
- **防泄漏**：一个快照只能用它 `cutoff_turn` **及之前**的对话；每条要素的「来源对话」轮次都必须 **≤ 本快照 cutoff**，绝不能引用后面才出现的信息。

### ⑦ 诉求原子化
- 能**独立成立 / 独立撤回**的诉求要**拆开**（本金一条、利息一条；换新一条、补偿一条），各自编号。
- 揉成一条会导致「只撤回其中一半」无法表达。

### ⑧ 算术自洽 + 描述稳定
- **算术**：方案 / 事实里的金额加减乘除要**算得对、前后一致**（减免、分期、折价、对冲都对得上）；带前提的成果别写成无条件达成。
- **描述稳定**：同一个编号的自由文本，**首次定稿后跨快照尽量保持一致**；只有**真有新信息**（新数字 / 新实质内容）才更新它——不要每个快照把同一件事换个说法重写一遍（那会制造无意义的「反复改写」）。

> **调解方案的 `策略话术` 单列一条要求**：话术要**扣本案具体事实 / 金额 / 当事人原话**；**禁**「多沟通 / 换位思考 / 我理解您的心情」这类放之四海皆准的空话；**禁**下判决、预判胜败、威胁、道德绑架。早期还没具体方案时，`内容`可留空、但`策略话术`可以先给「怎么谈」。

## 3. 检修维度（逐维度：判据 / 合格线 / 人工怎么查）

做完、改完，按下面**每一维**过一遍。「怎么查」全是人工手法，不需要任何工具。

| 维度 | 什么算错（判据） | 合格线 | 人工怎么查 |
|---|---|---|---|
| **编造** | 写了对话里根本没有的姓名 / 金额 / 证据 / 事件 | 抽检 ≈ **0** | 逐条要素回对话找出处；找不到 → 删或改回有据 |
| **归属安错** | 态度记给了没这么说的人（沉默者 / 被转述者 / 同姓他人） | 抽检 ≈ **0** | 每条态度点开它的「来源对话」轮次，确认**确实是这个人**说的 |
| **沉默/转述当认可** | 把没吭声、或调解员转述，当成当事人认可 | **0** | 凡标「认可 / 双方确认」，核两方是否**各有本人发言** |
| **状态越界** | 状态机字段用了词表外的词 | **100% 在词表** | 对照 §1.1 逐字段核；不在表里就改 |
| **状态↔态度打架** | 状态说「双方确认」但方态里有人「否认 / 未回应」 | **0** 自相矛盾 | 每条事实：`当前状态` 和它的 `各方态度` 必须对得上 |
| **编号裂号** | 同一件事被拆成两个号并存 / 数额变了就新开号 | **0** | 同案通读，看有没有「说的是同一件事」的两个号 |
| **编号不接续** | 新增号没接在该类型最大号后面 | **0** | 按 `claim_/fact_/issue_/evidence_` 各自顺号核 |
| **跨类重复** | 同一现实事项在 事实/争议/证据 重复登记 | **0** | 通读一案，一现实项只留一处主记录 |
| **擅删 / 漏带** | 前面有、现在仍有效的项，在后面快照消失了 | **0** | 把相邻两快照并排，看有没有项「无故蒸发」 |
| **未来信息泄漏** | 某条来源轮次 > 本快照 cutoff | **0** | 每条「来源对话」轮号必须 ≤ 本快照 `cutoff_turn` |
| **塌合键沉默** | 方态一个键塞「甲、乙、丙」共用一个态度 / 沉默者被并进去 | 逼近 **0** | 方态**一人一条**；没开口的人不出现在方态里 |
| **命名残留** | 出现「申请人 / 被申请人 / 某」等角色词占位 | **0** | 全案搜角色词 / 「某」，替成真名或留空 |
| **复合诉求未拆** | 本金+利息 / 换新+补偿 揉成一条 | 该拆的拆 | 看每条诉求是否「能被单独撤回」，不能就拆 |
| **算术不自洽** | 金额加减对不上 / 带条件写成无条件达成 | **0** | 把方案里的数字自己算一遍 |
| **描述乱改** | 同编号每快照换说法（无新信息） | 尽量 **0** | 跨快照追同一编号的自由文本，无新信息就应保持一致 |
| **话术空话/禁忌** | 空话套话 / 判决 / 威胁 / 道德绑架 | **0** | 逐条读 `参考话术`，是否扣本案、是否越界 |

> **哪些是硬指标、哪些是尽量**：状态词表 100% 在表内、未来信息泄漏 0、擅删 0、状态↔态度不打架、编号不裂号——这些是**结构性硬指标，必须清零**；编造、归属这类语义问题是**难点**，做不到绝对 0，但抽检必须**逼近 0**、发现即返修。

## 4. 怎么组织检修（没有脚本的团队，如何做到可靠）

1. **做检分离、双人交叉**：检数据的人**不是**做这条数据的人——人挑不出自己的错。
2. **回指来源核对**：查「编造」和「归属」的通用动作 = 每条要素点开它的「来源对话」轮次，回原文比对。这两维只能这么查，别偷懒。
3. **先结构、后语义**：先过「状态词表 / 编号 / 泄漏 / 状态↔态度」这些**肉眼快查**的结构维（快而准），再花时间过「编造 / 归属」这些要回读对话的语义维。
4. **严重项 ≥2 人复核再改**：单人初判**很容易把正常数据误判成问题（过报）**，凭一人判断就动手会越改越差。严重问题**至少两人独立看、都认为是问题**，再返修。
5. **只改被点到的地方**：返修时只动那一处，别顺手重写整条——顺手改最容易引入新错（如把对的金额改错、把在场人替成错的人）。改完和改前**逐案比一遍**，确认「只改了该改的」。
6. **抽样比例**：结构维建议**全量**过（快）；语义维（编造 / 归属）至少**交叉抽检 ≥20%**，发现集中问题就扩大到全量。

## 5. 交付前自查清单（逐项打勾，全过才交）

```
结构维（应全部为 0 / 100%）：
□ 状态机字段 100% 落在 §1.1 词表内
□ 无未来信息泄漏（每条来源轮次 ≤ 本快照 cutoff）
□ 无擅删（仍有效的项在后续快照继续带着，同号）
□ 状态 ↔ 各方态度 不自相矛盾
□ 编号：同事同号、数额变更新老号、不裂号、跨类不重复、按前缀顺延
□ 命名：无「申请人/被申请人/某」等占位，方态一人一条、沉默者不列

语义维（逼近 0，发现即返修）：
□ 编造：每条要素都能回对话指到出处
□ 归属：每条态度确实是「来源轮次」里那个人说的
□ 确认：凡「认可/双方确认」两方都有本人明确发言
□ 复合诉求已原子化；算术自洽；同编号描述无谓改写已消除
□ 策略话术扣本案、无空话、无判决/威胁/道德绑架

流程：
□ 做检分离，语义维交叉抽检 ≥20%
□ 严重项 ≥2 人独立复核后才返修
□ 返修只改被点到处，改完逐案比对前后
```

## 6. 诚实告知：两个天花板

- **归属安错** 和 **编造** 是本类数据的**固有难点**（对话本身信息不足时尤甚），不必苛求绝对清零；目标是抽检逼近 0、发现即修。
- 反过来，**结构性维度**（状态词表、编号、泄漏、擅删、状态自洽）**没有借口，必须 100% 干净**——它们靠规则就能查死，是验收的硬门槛。

## 7. 补充：不同人的诉求各自成条 + 难例配额（2026-08-07 新增）

> 前六节在「缺陷」上是齐的。这一节补两件之前没写、但线上真翻过车的事。

### 7.1 同阵营多人，诉求各自成条（硬规矩，补 §2）
- 同一方**多个人**（都是申请人方 / 都是被申请人方）各自提诉求时，**每个人的诉求单独成一条、单独一个编号**——哪怕两人诉求**内容几乎一样、甚至逐字相同**。
- ❌ 最常见的错：第二个人（张三）提了和第一个人（李四）几乎一样的诉求，就把它当成「李四那条诉求的更新 / 进展」，不给张三单独立条 → **张三在系统里凭空消失**。
- ✅ 对：李四提「减免物业费」＝ `claim_002`；张三也提「减免物业费」＝ **另起 `claim_003`**，各自独立跟踪、各自能被单独撤回 / 达成。
- 判据：**一条诉求换个人主张 ＝ 新的一条，不是老诉求的更新。人不同就是新号。**
- 和 §2⑤ 不冲突：**同一个人**改数额 ＝ 更新老号；**换了个人** ＝ 新号。
- 检修（新增一维）：通读一案，凡有同阵营第二人，逐个确认他的诉求**确实单独成条**、没被并进别人编号；发现即返修。

### 7.2 难例要占比例（别全做好做的）
- 「同阵营多人 ＋ 诉求同构」这类案子，和「背靠背 / 一对一单独沟通」的渠道，是**重点难例**，要在交付里占**相当比例**；别全交「对立双方、诉求各不相同」的好做案子。
- 尤其：**逐字 / 高度同构**的同阵营诉求（两人说的几乎一模一样）最容易被做错，恰恰最需要多做、跨不同纠纷类型都做。
